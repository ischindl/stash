    feat(STAS-330): complete Steps 2+3 — consume the wake comment delta instead of recomputing it

The comment half of a heartbeat wake was a pure recomputation: every wake
re-derived 'which steering comments are newer than my last run' from the card
and nothing recorded which ids an earlier wake had already put in front of this
agent on this card. STAS-270 therefore carried b3102332 / 46128b1a / 69516485 /
75217182 through 15+ re-wakes in two hours, resolving none of them.

- agents/wake-comment-delta.ts: the shared rule. consumeWakeCommentDelta
  subtracts the ids a prior run of this agent already advertised, read back from
  that run's own contextSnapshot.triggeringCommentIds, bounded by
  WAKE_COMMENT_CONSUMPTION_SCAN_RUNS and MAX_CONSUMED_WAKE_COMMENT_IDS;
  renderWakeCommentDelta renders body / loud not-on-this-card line / nothing and
  always reports the ids it advertised; isSelfAuthoredComment + selfAuthorKeys +
  selfAuthorKeysForTask + selectExternalSteeringComments decide self-echo, with
  an unknown author deliberately treated as external input.
- agent-heartbeat.ts: consumption runs at the wake's fire time inside
  executeHeartbeat, the one path every wake source (assignment, message,
  deferred re-fire) flows through, so a replay whose ids an earlier run already
  advertised arrives as a wake with no comment attribution; the run row keeps
  recording what it advertised. The delta block now renders through the shared
  renderer and withholds rows this agent authored.
- executor/execution-prompt.ts: the '## Steering Comments' section is extracted
  into buildSteeringCommentsSection and drops rows authored by the agent
  assigned to the card.
- executor/workflow-input-markers.ts + await-input-node.ts: both reply
  detectors now share workflowInputRepliesAfterWatermark, which also applies the
  author filter, so a workflow-input node can no longer satisfy itself with the
  executing agent's own steering.
