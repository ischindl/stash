# Reading of those lines, per line:
#   stdout+stderr are streamed into one accumulator: the child's two output
#     pipes share one sink, so stderr is indistinguishable from stdout here.
#   snapshot content is emitted verbatim as the single text content block.
#   emptyText substitution inserts the harness string '(no output)' when a
#     command produced nothing, and only then.
#   formatOutput APPENDS bracketed truncation notices naming the line range
#     and the temp file holding the full output -- harness text, but shaped
#     as a notice, never as a directive.
#   appendStatus APPENDS one of exactly four status strings (Command aborted
#     / Command timed out after N seconds / Command terminated without an
#     exit code / Command exited with code N). These are the only
#     non-command-derived strings this instrument can attach to a result.

## Assembly site named for AC3
# The one place a bash command's bytes become a model-visible content block
# is formatOutput in Instrument A's core/tools/bash.js, with appendStatus the
# only function there that adds non-command text. Instrument B contains no
# such site for this channel: it sanitises assistant text and persists
# results, so a hardening rule placed in B cannot reach this channel, and a
# rule placed at formatOutput edits an upstream dependency this repo does
# not own. That asymmetry is the whole cost of the AC3 proposal.
