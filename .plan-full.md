## What This Delivers

- Opening the integrations page (or any source page) shows the sources you never actually connected as "Needs setup" with a line saying exactly what is missing ("not connected to gmail"), instead of a red "Sync hit an unexpected error — it will retry automatically" that promises a retry that can never help.
- The background work queue stops filling itself with doomed sync attempts. On a freshly seeded dev machine, the queue stays empty instead of growing by ~300 jobs an hour forever, so the curator backfill gets its workers back and finishes.
- A revoked connection for a real user stops hammering the queue and instead asks for a reconnect, then resumes on its own cadence once they act.
- A sync that fails for a genuinely temporary reason (a network blip) still quietly retries on schedule.

## Before → After Transformation

- **Before:** "no credential / no API key" is a permanent configuration state but is raised as a raw HTTPException / RuntimeError, caught by the catch-all in _sync_source, recorded as failed + "will retry automatically", and re-dispatched by Beat every 120 s with no in-flight dedupe — a self-sustaining storm (measured: LLEN heavy 5,044 and rising; 13 seeded demo sources failing 57× each in 20 h) that starves the curator backfill.
- **After:** the same states park the source (needs_setup + an actionable message owned by mark_needs_setup), Beat claims a source atomically at dispatch so a source with a queued/in-flight sync is never enqueued twice, and seed_dev seeds its demo sources parked. On a fresh seeded stack the heavy queue stays ≈0 across ≥30 min; transient failures keep their normal retry cadence.

## Mission

Make source sync failure classification honest and dispatch idempotent. Permanent "you haven't connected this / this key isn't set" states must park a source in needs_setup (the state built for exactly that) instead of looping through failed + a retry promise; the Beat reconciler must claim what it dispatches so a stale backlog can't re-run a sync that is already queued; and the dev seed must not manufacture that load. This unblocks the founder's curator backfill (the heavy lanes) and, more importantly, removes the identical storm that a real user's revoked OAuth token causes in production.
