+/*
+STAS-397 guard: an automatic checkout release decides from OCCUPANCY only.
+
+Occupancy is content git counts as occupying a checkout - a tracked modification, a staged
+change, or an untracked path. A git-IGNORED path is not occupancy, so a checkout whose only
+content is ignored build output releases, and the case below named `ignored-only` IS the
+invariant this file installs. It is the state seven board cards sat in on 2026-08-11 while a
+half-hourly sweep retried a removal that could never succeed: `--untracked-files=all` empty,
+the tip an ancestor of the integration ref, zero commits ahead, and `.venv/` plus
+`stashai.egg-info/` on disk - a checkout produced by following this repository's own
+documented development procedure.
+
+The three refusal cases beside it are the other half of the contract and are NOT negotiable:
+each differs from the released case by exactly one porcelain class, and each must keep the
+content it is refusing to throw away. Weakening or deleting one of them to make a suite green
+trades the wedge for data loss.
+
+Like the real-git suites beside it, this file deliberately mocks nothing: a mock of the status
+probe would reproduce the defect's own blind spot, because the bug lives in how the real
+porcelain read is classified.

Subject: [PATCH 2/5] fix(worktree): decide a checkout release from occupancy,
 so ignored artifacts stop blocking forever

An automatic release asked whether each ignored path's BASENAME was on a hardcoded list of
well-known build and dependency directories, and refused when it was not. That question has no
stable answer: the list knew `.venv` but no `*.egg-info` shape, so a checkout created by the
documented dependency-install procedure of the repository it runs against could never be released,
and the one escape hatch was admitted for a single removal reason the sweep hitting it every half
hour is not allowed to use. Seven board cards held exactly that checkout.

Occupancy is what a release can actually ask about: a tracked modification, a staged change, or an
untracked path. Ignored content is probed, named in the release's own audit record, and never
blocks. Deleting the allowlist, the child-probed scratch exception and the ignored-only proof gate
leaves one predicate; the refusal for deliverable, unreadable and root content is untouched, so no
sweep destroys work it could not enumerate.

Retired: REGENERABLE_IGNORED_DIR_NAMES, FUSION_SCRATCH_REGENERABLE_CHILDREN,
isRegenerableScratchDirectory, the `regenerable-ignored` class, and the
worktree:post-landing-ignored-content-discarded and
worktree:removal-discarded-regenerable-content rows, replaced by
worktree:removal-discarded-ignored-content, which names the paths it discarded.
