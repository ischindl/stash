3. THE ATTRIBUTION ARITHMETIC, and why no trunk-tip run was made
==========================================================================================
AC4 requires a per-name single-file attribution run at the trunk tip for EVERY name in the
first list, and only for those names. The first list holds 0 names, therefore:
    attribution runs required = 0        attribution runs executed = 0
No detach to the trunk tip happened during Step 4 and none was needed; the scratch checkout
stayed at the candidate tip for all four instruments, which is also what keeps the tested tip
and the SHA the GREEN capture names the same object.
The same rule was applied to the other three instruments: both typechecks and the static gate
returned 0 at the candidate, so no inherited-or-introduced question arises for them and none
was measured at the trunk tip. Had any of them been nonzero at the candidate, AC4 requires
running it at the trunk tip and labelling it, and that label would have gated Step 5.
Reaching another tree, if it had been needed, is by checkout --detach and never by git stash,
because the engine's stash list is shared across all its worktrees on this host.

4. POSTGRES - why no throwaway cluster was started
==========================================================================================
190 of the 264 names are pg-gated and fail on this host's authentication baseline
(PostgresError: password authentication failed for user "schindler", code 28P01), identically
on both sides. AC4 needs a database only to attribute a NEW failure, and there are none, so the
repository's own throwaway cluster (root scripts pg:test:up / pg:test:status / pg:test:down ->
scripts/pg-test-server.mjs) was neither started nor needed. Its existence is recorded so the
absence is not read as a silent skip: no row was skipped, every one of the 264 names appears on
both sides of the difference.
